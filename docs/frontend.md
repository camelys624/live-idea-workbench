# 前端工作台：投稿、范围审核与关系整理

React + TypeScript + Vite CSR，沿用 npm workspaces。`@workbench/contracts` 是请求 schema 和 DTO 的唯一来源；没有另建 API 类型副本，没有引入 SSR、路由框架、客户端 CLI 或部署身份。

## 页面与文件

按 v2 设计稿实现白灰底色、细边框、黑色主按钮及紫色品牌/选中态。桌面为导航、投稿列表、详情三栏；900px 以下为列表/详情独立视图，导航使用 Sheet 抽屉，详情页签排成两列。三功能及完成标准优先呈现，全部期望独立保留，审核操作栏固定底部并预留 safe-area 和内容空间。

| 文件 | 行为 |
|---|---|
| `apps/web/src/App.tsx` | 桌面三栏、移动导航 Sheet、详情 Tabs、收件箱/待审及状态筛选、游标分页、身份与实时刷新 |
| `SubmissionPanels.tsx` | 人工/示例录入、来源消息去重结果、不可变原文、完整整理字段、观众优先项、归属历史 |
| `ReviewPanels.tsx` | 三项编号功能卡与标准、保留草稿的折叠编辑器、范围/批准历史、受控 AlertDialog 审核确认 |
| `RelationshipPanel.tsx` | 真实目标列表、整体合并、单条重复/反馈归属、来源与目标确认、合并和反馈历史 |
| `ExecutionPanel.tsx` | 当前批准、独立立项、人工分配、独立启动、执行查询与未知作业对账；远端记录与请求受理分开 |
| `AiPanel.tsx` | AI 判断历史、依据、失败及人工重试、三功能参考建议、实际待审任务快照 |

录入入口默认人工，填入示例会明确切换到 `sample`；不自动种入假投稿。原文不可编辑；整理字段、全部期望和观众优先项独立呈现。作者可空，不新增服务端契约以外的必填限制。

详情页签使用 `forceMount`，非激活页签由 CSS 隐藏；返回列表、同一创意重新打开、收起编辑器不会卸载草稿。审核和关系确认由 Radix 控制焦点与模态状态，确认按钮不会提前关闭弹窗；服务器错误和过期范围保留捕获内容，成功后才关闭。UUID/审计信息放在可展开区域，不删记录。原文按文本渲染，不执行 HTML 或指令。

设计稿中的全量搜索/统计与聚合项目导航尚无后端契约，因此未伪造这些能力。只显示已加载数量，项目与反馈导航打开所选创意的真实详情。表单选择器保留原生 `select` 与禁用 `fieldset` 语义；不把“装了 shadcn npm 包”当成已使用组件的证据。

## 状态与并发边界

- 保存本次范围不等于批准。表单固定三项，使用共享 schema 校验每项标题、完成标准和页面范围；服务端最终校验。
- 批准、退回、拒绝先展示版本、三个功能及审核理由，再显式确认。权限来自 `/api/me`，不是前端自行声明角色。
- 草稿绑定打开时的 `baseVersionId`，SSE 不自动更换依据。新范围到达后保留草稿并禁止过期提交，需人工核对并丢弃/加载当前版本。服务端 `STALE_SCOPE_VERSION` 同样阻止继续使用旧依据。
- 范围修改会新建版本并作废旧批准。界面同时展示最新版本、当前有效批准和历史，不把历史批准误作当前批准。
- 刷新、临时只读、断线、页签切换、收起编辑器和移动端返回列表不会卸载同一创意的草稿。切换到另一创意或重新载入页面不保留旧创意的内存草稿；显式放弃或相应保存成功才更新当前草稿。
- 整理字段 API 暂无并发版本参数；前端可保留草稿，但不能保证多操作员整理字段的乐观锁。原文和范围版本的不变量仍由后端保证。
- 整体合并与单条归属是不同操作。目标由服务器分页返回，不默认选择目标。理由和来源/目标需明确确认；成功前不乐观移除记录。
- 当前服务端禁止单独移走 `origin`，页面引导整体合并；`duplicate`/`feedback` 可按服务端规则重新归属。反馈归属的是现有创意 ID，尚非真实 Multica 产品项目记录。

## 断线、失败与敏感操作

SSE 使用 `/api/events`，收到 ID 事件重新读取；每次连接/重连拉取当前列表和详情，因为服务端不补发漏掉的事件。手动“刷新数据”会重新建立 SSE 并读取权威状态，不能重放先前写操作。SSE 未连接时停用写入，草稿仍可查看。

API 请求含响应体读取的期限为 15 秒。网络断开、超时或无有效确认体不会报告写入成功，也不自动重试。显示“结果待核实”，保留输入；先刷新后再由人工决定下一步。身份查询失败时关闭可能被代理悬挂的 SSE 连接，明确显示访问异常和断线，并停用操作。恢复后由手动刷新重新核实数据；EventSource 自身的正常断线重连仍刷新权威状态。

401/403 有明确身份/权限提示；5xx 不透传敏感服务端错误。前端禁用不是安全边界，Fastify 的角色校验和范围版本校验仍是权威。浏览器不发送代理共享密钥或自选身份；仅本地 smoke 使用已有 `AUTH_MODE=dev` 的身份模拟能力验证角色边界。

## 本地运行和构建

按根 README 配置仅限本机的数据库与后端 `.env`，启动数据库、迁移及后端，然后在另一终端运行 `npm run dev:web`，地址 `http://127.0.0.1:5173`。Vite 只监听 `127.0.0.1`，代理 `/api` 到同机 3000 端口；这不是生产部署或生产身份代理。

- `npm test`：服务端已有 PostgreSQL 集成测试 + 前端 API 不确定写入/超时、草稿保留与过期范围回归测试。
- `npm run typecheck`：所有 workspace strict TS 检查。
- `npm run build`：生成 `apps/web/dist`；生产需按 ROBB-8/14 的部署方案从同一受控来源提供静态文件与 `/api`，不使用 Vite 开发服务公开部署。

React/React DOM、Vite 和 npm workspaces 保持原有技术栈；不引入 SSR、路由或状态框架。按设计接入 shadcn/ui 源码、Radix 交互与 lucide 图标，Tailwind v4 和动画 CSS 为组件构建所需；组件源码随项目维护，`components.json` 记录来源风格与别名。Testing Library/jsdom 只用于草稿和确认边界回归，不进入生产包。

## ROBB-11 前端接续（2026-10-19）

沿用 `packages/contracts`，没有增加浏览器侧凭据、假 API 或默认 agent。AI 和执行面板使用 React 自带的 `lazy` / `Suspense` 拆为异步模块，详情页签仍保持挂载以保留人工选择和确认状态。

- 配置区默认折叠，分别显示 AI / Multica 的 `not_configured`、`invalid`、`configured`、检查项及写入/启动开关。`configured` 仅表示本地配置完整，不表示远端连接、权限或模型额度已核验。读取失败明确标记旧摘要不可作为当前状态。
- AI 显示判断依据、模型错误、参考三功能、建议目标及历史；建议不会自动修改范围、批准或合并。仅 operator、全部相关投稿为模拟人工/示例、配置和平台历史均可核实时允许人工确认请求。已有 pending 判断、unknown 作业或未结束的平台作业阻止重复提交。
- 独立立项只接受当前有效批准；dispatcher 选择 agent 和确认分配，launcher 另行确认启动。选择从空开始，批准/产品/分配变化会清空选择。任务状态、运行状态和平台作业状态分别显示，不把 HTTP 202 当作创建/启动成功。
- agent 检查归档、runtime 绑定/在线及调用权限；执行/agent 查询超过 30 秒停止相关写入，需人工刷新。启动确认最终提交前再次读取执行及依赖，拒绝已变更的 assignee、批准或任务状态。未知运行状态原样标为未知，不当作完成。
- 平台 unknown 作业只能人工对账；`found` / `absent` / `ambiguous` 分别展示，不自动重建。未确认的新作业和网络不确定结果会锁住再次写入，切换创意或面板重挂载不能绕过此锁。
- `platform.updated`、当前创意更新、重连和人工刷新读取配置/平台记录。请求用取消与序号隔离，旧创意的迟到响应不能覆盖新创意。404、读取失败、断线及权限丢失不会变成空记录或成功状态。
- Chromium 实测发现快速取消再打开时，Radix content 与 overlay 同为 z-50 可被重排后的 overlay 遮挡；content 改为 z-51，实际取消/重新打开/确认流程已验证可点击。

### ROBB-11 后端接续交接

`apps/server/src/app.ts` 已提供上述全部共享契约路由；无需前端更换路径或 DTO。立项首次 202/重复 200，响应和 SSE 指向持久操作结果，HTTP 成功本身不代表远端写入成功。作业目前在请求内执行，前端继续按 `pending/running/succeeded/failed/unknown` 展示并重读；不存在后台自动重试。真实 Multica 未配置时平台历史仍可读（空历史不是 404），模型未配置仅禁用 AI 操作，人工投稿/审核不受影响。
